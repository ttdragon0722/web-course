URL 解析

一條網址，其實藏著「去哪裡、要什麼、怎麼要」的完整指令 —— 用顏色拆給你看。

https://api.example.com:8080/users/42?sort=asc&limit=10#profile
區段內容意義
協定https://用什麼方式溝通（加密的 HTTP）
主機api.example.com要連到哪一台 server
埠號:8080連到 server 上的哪個門
路徑/users/42要哪個資源（第 42 號用戶）
查詢字串?sort=asc&limit=10附帶條件（排序、數量）
片段#profile頁面內定位的位置

而使用者是否收到？

每一次請求，後端都會回一組「狀態碼（Status Code）」告訴你結果。

常見 Status Code

  • 200 OK — 成功
  • 202 Accepted — 已接受，處理中
  • 400 Bad Request — 請求格式錯誤
  • 404 Not Found — 找不到資源

分類各代表什麼

  • 1xx 資訊：請求已收到，繼續處理
  • 2xx 成功：已被接收、理解、接受
  • 3xx 重新導向：需進一步動作才能完成
  • 4xx 用戶端錯誤：請求語法錯或無法滿足
  • 5xx 伺服器錯誤：server 處理時出問題

怎麼看懂別人的 API？　上 · 先讀網址

很多服務都開放公開 API —— 學會「讀」它，你就能直接拿別人的資料來用。以 Chess.com（西洋棋）查某位玩家的對局為例：

https://api.chess.com/pub/player/ttdragon0722/games/2026/05

① 網址一段一段拆開看

api.chess.com專門放 API 的主機
/pub公開資料（public）
/player/ttdragon0722哪一位玩家
/games/2026/052026 年 5 月的對局

② 讀網址其實在問三件事

  • 去哪裡？　主機 api.chess.com
  • 要什麼？　路徑 /player/.../games
  • 哪一筆？　參數 /2026/05

公開 API 直接把網址貼進瀏覽器就看得到 —— 不用先寫程式。

心法（上）：網址就是一句指令 —— 把路徑一段一段拆開，「它想給你什麼」大概就猜到一半了。

怎麼看懂別人的 API？　下 · 看懂回傳

把上一頁的網址打開後，後端會回給你一包 JSON。重點不是「全部看懂」，而是抓出你要的欄位。

③ 它回傳的 JSON 長這樣

{
  "games": [
    {
      "url": "chess.com/game/live/169..",
      "time_class": "blitz",
      "rated": true,
      "white": {
        "username": "ttdragon0722",
        "rating": 322,
        "result": "win"
      },
      "black": { ... }
    }
  ]
}

④ 怎麼讀懂這些欄位

  • 看欄位名猜意義：rating(分數)、result(勝負) 一看就懂
  • 看外層結構：最外面是 games 陣列 [ ] —— 一筆筆對局
  • 注意巢狀：white / black 底下還各包一個物件
  • 看不懂就查官方文件（Chess.com 有 Published-Data API）

04 · 重點總結

5 個帶得走的重點

1
IDE — 把工具練熟
  • VS Code 能開發各式各樣的程式，不只寫網頁
  • 工具用得熟，就能事半功倍
  • 善用快捷鍵與延伸模組，甚至能自己開發模組
2
HTML / CSS — 設計靠細節累積
  • 前端框架 Tailwind 上限高，很多設計都是從它開發出來的
  • 設計的眉角，是一點一滴的細節累積上去的
  • 多看日本／國外網頁找靈感，記住常見元件名：Hero SectionCarousel 旋轉木馬
3
JavaScript — 什麼都能做
  • 它就跟一般程式語言一樣，能做到很多事
  • App 開發、爬蟲、後端程式碼……都行
4
動畫 — 值得再深入
  • 這部分今天沒講透，動畫庫很值得專研
  • 關鍵字：three.jsGSAPScrollTrigger
  • 跟 AI 溝通時，直接丟這些關鍵字效果更好
5
保持持續學習的態度
AI 的開發速度越來越快 —— 持續學習更多 AI 知識、提示詞工程（Prompt Engineering）與各種 AI 工具，才是真正的競爭力。

05 · 動手做

實作目標

主題：做一個「虛構品牌的單頁官網」—— 手搖飲店、你最愛的遊戲 / 偶像、貓咪咖啡廳、個人作品集……主題自選，挑一個你有感覺的。
必做 — 5 關都要過
  • 一個 Navbar（用到 Tailwind 的 flex / 間距）
  • 一個 Hero Section（大標題 + slogan + 一個按鈕）
  • 至少 3 張卡片 Card（排成一排，手機上會換行）
  • 一個 JavaScript 互動 三選一：選單收合 / 深色模式切換 / 計數器按鈕（+1）
  • 用 Tailwind 排版，手機、電腦都不跑版（RWD）
加分 — 行有餘力再挑戰
  • 一個動畫（hover 變色、淡入，或試 GSAP ScrollTrigger）
  • 一個 Carousel 旋轉木馬

先把「必做」做完再碰加分；加分沒做不扣分，做了是亮點。

Prompt — 講師示範

同一個 AI，會不會用差很多 —— 先學「怎麼開口」。給你一個起手式：

你是一位資深前端工程師。 請用 HTML + Tailwind 幫我做一個「手搖飲店」的單頁網站， 要包含 navbar、hero section、3 張卡片。 # 先只給我 HTML 結構，不要 JavaScript —— 我要自己看懂再慢慢加
  • 結構化：先講目標 → 再給細節 → 最後加限制
  • 先要「結構」不要 JS：逼自己看懂每一段，而不是一次吞下全部
  • 角色扮演：開頭先設定身份，回答品質會明顯不同
真的不知道怎麼寫？先請 AI 幫你「潤稿」，潤完再拿去生成 —— 永遠比亂寫好。

實作方向

照這個節奏推進；卡住了先自救，再來問我。

推進五步
  1. 選一個你有感覺的主題
  2. 用起手式 Prompt 生出 HTML 骨架
  3. 一段一段看懂，改成你的內容
  4. 加上一個 JavaScript 互動
  5. 用手機尺寸看一下會不會跑版
卡住了怎麼辦
  • 先按 F12 看 Console 有沒有紅字
  • 不會排版就查 Tailwind 關鍵字：flex gap grid
  • 問我時帶上「你試過什麼、錯在哪」
我是你的除錯教練，不是代工 —— 我給你關鍵字和方向，code 你自己改。
