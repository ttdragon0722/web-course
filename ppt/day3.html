JS 做什麼用？

HTML = 骨架，CSS = 皮膚，
JS = 房子的電路（讓網頁動起來）。

最簡單的互動

// 點按鈕跳出訊息
document.querySelector('#btn')
  .addEventListener('click', () => {
    alert('你點到我了！');
  });

三個核心能力

DOM 操作
改變頁面內容 — 新增、修改、刪除畫面上的元素。
事件處理
監聽使用者的點擊、輸入、捲動等動作並做出反應。
非同步請求
向後端要資料（fetch API），不重整頁面就更新內容。

jQuery — 舊時代的產物？

// 原生 JS — 選取所有 .card 加 class
document.querySelectorAll('.card')
  .forEach(el => {
    el.classList.add('active');
  });

// jQuery — 同樣的事
$('.card').addClass('active');
  • jQuery 讓 DOM 操作簡單 10 倍
  • 2024 年瀏覽器原生 API 已經很強
  • React / Vue 直接解決更根本的問題：狀態同步
歷史脈絡：jQuery → 解決 DOM 繁瑣 → React → 解決狀態管理。

React 核心概念

為什麼 Facebook 要發明 React？

  • 傳統做法：資料變了 → 手動找 DOM 元素 → 手動更新
  • React 做法：資料變了 → 畫面自動重新渲染
你只管「資料長什麼樣」，畫面交給 React 同步。

Component 思維

整個 Facebook → 切成小組件
├── Navbar
├── NewsFeed
│   └── Post   # 可重複使用
│       ├── Avatar
│       ├── Content
│       └── LikeButton
└── Sidebar
把複雜畫面拆成一個個可重用的積木。

React 舉例 — 一個複雜的 Header

一段含狀態、事件、清單渲染的 Header 元件 —— 看起來不少，但可以被「打包」。

Header.tsx 
import { useState, useEffect } from 'react';

export function Header() {
  const [open, setOpen] = useState(false);
  const [query, setQuery] = useState('');
  const links = ['首頁', '產品', '定價', '關於'];

  useEffect(() => {
    const onScroll = () => setOpen(false);
    window.addEventListener('scroll', onScroll);
    return () => window.removeEventListener('scroll', onScroll);
  }, []);

  return (
    <header className="nav">
      <div className="logo">◆ Brand</div>
      <nav>{links.map(l => <a key={l}>{l}</a>)}</nav>
      <input value={query} onChange={e => setQuery(e.target.value)} />
      <button onClick={() => setOpen(!open)}>選單</button>
    </header>
  );
}

React 狀態管理 — useState

import { useState } from 'react';

function Counter() {
  // 宣告狀態
  const [count, setCount] = useState(0);

  return (
    <div>
      <p>點了 {count} 次</p>
      <button onClick={() => setCount(count + 1)}>
        +1
      </button>
    </div>
  );
}

關鍵概念

count 變了 → React 自動重新渲染這個組件。

不需要再手動寫：

// ❌ 傳統繁瑣寫法
document
  .getElementById('count')
  .innerText = count;
  • 狀態（state）＝會變動的資料
  • setCount 一呼叫，畫面跟著更新

04 · 學習心法

關於與 AI 的學習與協作

在教學階段，我傾向還是去看懂程式碼。

AI 確實很強

  • 可以快速建立一個完整的開發環境
  • token 足夠時，甚至一行程式碼都不必看懂，也能做出作品
  • 實務上，未來大量工作可以交給 AI 完成

但學習階段不一樣

  • 初期與學習階段，自己要看得懂
  • 簡單任務上，看懂能省 token、更快完成
  • 看懂程式碼，才有能力判斷 AI 寫得對不對
結論：把 AI 當「加速器」，而不是「黑盒子」 —— 學習期先求懂，實務期再求快。

環境建立

建立 React 專案

# 經典做法
npx create-react-app my-app

# 或（更快、現代做法）
npm create vite@latest my-app \
  -- --template react-ts

cd my-app
npm install
npm run dev

專案結構解說

my-app/
├── src/
│   ├── App.tsx      # 根組件，從這開始改
│   ├── main.tsx     # 入口點，不用動
│   └── components/  # 你的組件放這
├── public/          # 靜態資源
└── package.json     # 依賴清單
