01 · 全端架構

前端 / 後端 / 資料庫 — 三者關係

使用者點按鈕
↓
前端（React）發 HTTP Request
↓
後端（FastAPI）處理邏輯
↓
資料庫（MySQL）存取資料
↓
後端回傳 JSON
↓
前端更新畫面

用「餐廳」來比喻

前端 = 餐廳大廳
客人看得到、會互動的地方 —— 點餐、看菜單、收到餐點。
後端 = 廚房
客人看不到，負責處理訂單、烹調 —— 真正的邏輯都在這裡發生。
資料庫 = 食材倉庫
存放所有原料，廚房需要時才去拿、用完再補。
前端負責「呈現」，後端負責「邏輯」，資料庫負責「儲存」。

02 · Next.js 與路由

Next.js — 為什麼 React 還不夠？

React 的問題

  • 純前端渲染 → SEO 很差（Google 爬不到內容）
  • 沒有路由系統 → 要自己裝 React Router
  • 沒有後端 → API 要另外建專案

Next.js 解決方案

  • SSR（Server-Side Rendering）→ SEO 友好
  • 檔案即路由 → app/about/page.tsx 就是 /about
  • API Routes → 後端直接寫在同一個專案
Next.js = React + 路由 + 後端 + SSR，一個框架把「前後端」收進同一個專案。

URL 完整解析

一條 URL 其實藏著很多資訊，看懂它才知道請求往哪裡送、帶了什麼。

https://api.example.com:8080/users/42?sort=asc&limit=10#profile
區段名稱說明
https://協議加密傳輸（HTTP over TLS）
api.子域名主域名下的分支服務
example.com主域名網站的識別名稱
:8080通訊埠省略代表預設（https 為 443）
/users/42路徑 Path要存取的資源位置
?sort=asc&limit=10查詢參數Query String，附帶的條件
#profile錨點 Hash前端用，定位頁面位置

基於以上，Next.js 可以做到什麼？

Next.js 用「檔案系統」當作路由與行為的約定，把上面這些概念全包進專案結構裡。

檔案即路由
資料夾結構直接對應 URL 路徑，不必手寫路由表。
特殊檔案約定
loading、error、not-found 等檔名各自有預設行為。
前後端同專案
API Routes 讓你在同一個 repo 同時寫前端與後端。
SSR / SEO
伺服器先渲染好內容，搜尋引擎能爬到，首屏更快。
巢狀 Layout
共用外框（Navbar / Sidebar）跨頁面保留、不重繪。
Parallel / 動態路由
同頁同時渲染多個區塊、或用 [id] 接動態參數。
參考：Next.js 官方 File Conventions — nextjs.org/docs/app/api-reference/file-conventions

Next.js 架構 — layout 與 page

  • 包住底下所有 page，跨頁保留不重繪

常用 File-system Conventions

在 app/ 底下，特定檔名 = 特定行為。以下是最常用的幾個約定檔。

layout.tsx
共用外框，包住子頁面、跨路由保留。
page.tsx
該路由實際顯示的頁面內容。
loading.tsx
載入中自動顯示的 Loading UI。
error.tsx
該區段出錯時的錯誤畫面（錯誤邊界）。
not-found.tsx
找不到資源（404）時顯示的畫面。
default.tsx
Parallel Route 沒有對應內容時的後備畫面。

03 · 串接與後端

Frontend ↔ API ↔ Backend

API 是前後端之間的「合約」—— 前端不需要知道後端怎麼做，只要照約定送請求、收 JSON。

同一份 API，網頁、App、第三方都能呼叫 —— 這就是「前後端分離」的價值。
03 · 串接與後端
03 · 串接與後端

FastAPI 基礎

main.py 
from fastapi import FastAPI

app = FastAPI()

@app.get("/users/{user_id}")
def get_user(user_id: int,
             include_posts: bool = False):
    return {
        "id": user_id,
        "name": "John",
        "posts": [] if not include_posts
                 else ["post1"],
    }

啟動服務

uvicorn main:app --reload

自動文件

  • 打開 http://localhost:8000/docs
  • 可以直接在瀏覽器測試 API
  • 路徑參數 {user_id} 對應 URL 的 Path
  • 函式參數 include_posts 自動變成 Query 參數
型別寫清楚 → FastAPI 自動驗證、自動產文件。

資料庫設計 — MySQL 基礎

關聯式資料庫概念

-- 使用者表
CREATE TABLE users (
  id      INT PRIMARY KEY AUTO_INCREMENT,
  name    VARCHAR(100) NOT NULL,
  email   VARCHAR(255) UNIQUE NOT NULL,
  created_at DATETIME DEFAULT NOW()
);

用外鍵建立關聯

-- 文章表（外鍵連到使用者）
CREATE TABLE posts (
  id      INT PRIMARY KEY AUTO_INCREMENT,
  user_id INT NOT NULL,
  title   VARCHAR(200),
  FOREIGN KEY (user_id)
    REFERENCES users(id)
);
一個使用者可以有多篇文章 —— 用 FOREIGN KEY 把兩張表連起來。
這部分你們未來上課會再深入（學校必修課），這裡先建立直覺即可。

Query 概念 — 用網址帶參數

YouTube 的 youtube.com/watch?v=dQw4w9WgXcQ —— 那個 ?v= 後面就是影片 ID。 同一個頁面，靠 Query 參數決定要播哪支影片；Next.js 也能用 searchParams 做到一樣的事。

id → API → Backend → Database 查出資料 → 再一路傳回前端顯示。
